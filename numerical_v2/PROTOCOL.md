## Actor arithmetic certificate

The exact binary tensor values and saved observation define an independent
rational affine reference for each layer. The reference has no BLAS summation
order. ReLU is applied to those exact rational values. A 100-digit decimal
calculation bounds tanh on the declared logit domain [-100,100] within 1e-60.
This reference checks the actual native actor calculation. It is not substituted
for the actor when computing dispatched coordinates.

The affine error calculation uses binary32 unit roundoff 2^-24 and
gamma(m) = m*u/(1-m*u), with m = 2*n+2 for an n-input affine output. Each output
bound combines the propagated input error with gamma(m) times the absolute
weighted input and bias sum. A normal-number floor also includes the absolute
partner sums for denormals-are-zero operands and the m rounded operation outputs.
It covers flush-to-zero behavior without assuming that a tiny operand's large
partner is bounded by one. Overflow and an unsupported domain stop preflight.
The same formulas apply to every layer without coefficients fitted from the
observed Mac/Linux discrepancy. An absolute-term-sum check also bounds products
and partial sums; a small final value after cancellation cannot excuse possible
binary32 intermediate overflow.

The actual tanh output must additionally lie within 2^-23 plus 1e-60 of the
independent tanh reference at its actual logits. This is an explicit tested
kernel-accuracy condition, not a claim that every Torch implementation satisfies
it. Tanh's unit Lipschitz bound propagates logit uncertainty. The box unscale
adds 3*gamma(4) and four normal-number floors. The coefficient decoder propagates
the resulting action radius through half the interval width and a binary64
gamma(8) rounding allowance. Both the actual and archived coefficient triples
must satisfy the resulting reference envelope and physical box.

The relevant primary documentation is Python's
[decimal reference](https://docs.python.org/3.10/library/decimal.html) for the
correctly rounded exponential and PyTorch's
[numerical accuracy note](https://docs.pytorch.org/docs/main/notes/numerical_accuracy.html)
for the distinction between mathematical and bitwise cross-platform agreement.
The preflight preserves full stage checks rather than granting validity from
a version string or deterministic-algorithm flag.
